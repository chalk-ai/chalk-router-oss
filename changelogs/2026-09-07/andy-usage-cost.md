- Report an estimated cost with every usage aggregate. `QueryUsage` rows now carry `estimated_cost_usd` and `unpriced_request_count`, filling the columns the Chalk dashboard's usage breakdown table already reads. Each call is priced against the checked-in rate card when it is recorded, into a new nullable `usage_events.estimated_cost_usd`, so a row grouped by API key, usage pool or connection sums costs that were each computed from the model that actually produced them — pricing at read time cannot do that, because such a row has no single model to price against.
- Keep an unpriced call out of the estimate rather than counting it as free. A model absent from the rate card stores NULL, which is deliberately distinct from a priced `0.0` (a fully cache-read call), and the query reports how many calls a row is missing through `unpriced_request_count`. Calls recorded before this change are unpriced for the same reason and show up in the same count.
