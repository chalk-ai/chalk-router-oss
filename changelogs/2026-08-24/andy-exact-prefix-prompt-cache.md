- Add **exact-prefix prompt caching**: the router can answer a request from a cache of finished completions instead of calling a provider. The key is a SHA-256 digest of the exact conversation prefix — every message, in order, byte for byte — plus every generation parameter that can change the answer. No similarity matching: two requests share an entry only when they are the same request.
- Caching is **opt-in per API token**, via `permission.cache` on the key (`CachePolicy` in the proto / admin API). `scope` picks how far a cached answer travels: `model` (every token in the environment), `team` (the key's usage pool, degrading to `token` when it has no pool), or `token` (the default — nothing shared between keys). Every scope is already partitioned by model and by Chalk environment, so no scope can serve one model's answer for another, or cross a tenant boundary. `ttl_secs` and `max_entry_bytes` are optional per key and inherit (and are clamped to) the deployment's.
- The cache sits **above the provider adapters**, so it is provider-independent — a `chalk/*` route that moves between OpenAI, Bedrock, and vLLM keeps its cache — and covers **both streaming and non-streaming** on both surfaces. `/v1/chat/completions` stores the canonical non-streamed completion, so a streamed and a non-streamed ask for one prompt share a single entry (a streamed miss is assembled from the deltas; a streamed hit is re-emitted as SSE). `/v1/messages` stores the upstream bytes verbatim — JSON body or whole SSE stream — and replays them unchanged; there `stream` is part of the digest. `/v1/messages/count_tokens` is never cached.
- The storage backend is pluggable behind a `PromptCache` trait, selected by `ROUTER_PROMPT_CACHE_BACKEND`: `disabled` (default), `memory` (in-process, bounded on both entry count and total bytes, true LRU with per-entry TTL), or `valkey` (alias `redis`; shared across replicas, lazy connect, 250 ms per-command deadline, server-side expiry). No backend is load-bearing — an unreachable or misconfigured cache serves uncached rather than failing requests or refusing to boot. Tuned with `ROUTER_PROMPT_CACHE_{URL,NAMESPACE,TTL_SECS,MAX_ENTRY_BYTES,MAX_ENTRIES,MAX_BYTES}`.
- The cache is consulted **after** the API key's permission gate — a hit is never a way around the allowlist — and **before** the judge, since judging exists to pick a model for a call a hit means we won't make. Only a *finished* generation is stored, so a stream severed mid-answer can never be replayed to a later caller as a complete one. Cache hits do **not** record usage: no upstream call was made, and billing the hit would double-charge the completion that populated it.
- Callers see `x-chalk-cache: hit|miss` with `x-chalk-cache-key` / `x-chalk-cache-age` (absent entirely for a key that never opted in); the same decision lands on the span as `chalk.router.cache.{status,scope,backend,key,age_secs}`.
- Fix: the Anthropic SSE span tap finalized on `message_stop` *before* the terminating chunk was buffered, so a streamed `/v1/messages` response was silently never cached. Found by the new integration coverage.
