- Extend the model fallback policy to streaming chat completions, retrying alternates before the `200 OK` is committed (RFP-0002). A streamed request whose primary fails to open now fails over transparently and reports the winner via `x-fallback-model` / `x-chalk-routed-model`.
- Bound each streaming candidate's connection-open with `ROUTER_STREAM_OPEN_TIMEOUT_MS` (default 10000) so a stalled provider falls over instead of hanging. Only the open is bounded; the response body streams unbounded.
- Fix: a fallback candidate that is *skipped* — because it failed strict resolution, or the API key isn't permitted to reach it — no longer replaces the real upstream error. Previously an authorized request whose primary returned `502` and whose only alternate was denied answered `403`, and a primary `429` lost its `Retry-After` header. The client now always sees the last genuine dispatch failure.
- **Behavior change:** chat fallback no longer retries request-shape errors (`400`, `413`, `414`, `415`, `422`, `431`); those return immediately instead of walking the whole alternate list to return the same error. Upstream-specific failures still fail over, including `401`, `402`, `403`, `404`, `408`, `429`, 5xx, and transport or credential failures. Affects the non-streaming path, which already had fallback.
