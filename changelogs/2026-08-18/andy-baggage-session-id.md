- read the caller's W3C `baggage` header and stamp its `session.id` onto every span the router starts, so an LLM call made on behalf of an agent conversation is attributable to it. Chalk groups a trace into a session by the `session.id` *span attribute*, and the router's `chat.completion` span is the one carrying `llm.token_count.*` — so with the id only ever in the request context, per-session token totals could not be read off the router's own spans at all. `extract_parent_context` previously copied only `traceparent`/`tracestate` into the carrier and the global propagator was trace-context-only, so inbound baggage was dropped twice over; both now include it, and a `SessionIdSpanProcessor` on the tracer provider copies the id onto each span at start rather than at each span site, so a span added later cannot silently leave its session behind. A request without baggage, or with baggage naming no session, stamps nothing.
