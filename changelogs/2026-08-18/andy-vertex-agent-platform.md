- add a `vertex` provider connection kind for Vertex AI (Google Agent Platform, fka Vertex), so Gemini is reachable on the enterprise surface and not only through Google AI Studio. The existing `gemini` kind is the Developer API and takes a standing API key, which Vertex does not accept at all — it authenticates with an OAuth2 token that expires in about an hour, scoped to a GCP project and region. A `vertex` connection therefore stores the **service account key JSON** (the blob GCP downloads, holding a PEM private key) as its credential: the router signs an RFC 7523 JWT-bearer assertion with that key, exchanges it for a `cloud-platform` access token, caches the token, and refreshes it two minutes ahead of expiry, with concurrent requests on a cold cache minting one token between them rather than one each. The key never leaves the process, and every type that holds it has a hand-written redacting `Debug`. The project is read from the key; the region defaults to `us-central1` and moves via a `"location"` field in the key JSON or a `base_url` pointed at another `https://<region>-aiplatform.googleapis.com`. Chat and streaming go through Vertex's OpenAI-compatible endpoint (bare model names are qualified with the `google` publisher, partner models keep theirs), embeddings are translated to the native `:predict` call that Vertex serves them on, and image/audio/moderation return an explicit error instead of silently routing elsewhere. `gcloud`'s `authorized_user` credentials work too, sending the `x-goog-user-project` header that `aiplatform.googleapis.com` requires of user credentials — and that a service account must not send, since it would additionally demand `serviceusage.services.use`.
