- Sample LLM-frontend traces against a DB-backed, admin-editable policy (`SamplingPolicyService`): an ordered list of match rules, where the first rule whose every stated condition (`request_tag` from the new `x-chalk-request-tag` header, `key_id`, `usage_pool_id`) matches a request supplies its keep rate, plus a `default_rate` for requests no rule matched and a conversation rate floor. Rule order is the precedence; a rule with no conditions is rejected so `default_rate` stays the only catch-all. The decision is a deterministic hash of the caller's `session.id`, so every request of one conversation is kept or dropped together; `x-chalk-force-trace` forces a trace for debugging.
- Resolve each frontend trace's keep decision once, at request entry, and propagate it to every span of the trace as baggage, so a request's spans that carry no LLM attributes of their own — the `policy_cache_refresh` the fallback and judge policy stores open mid-request — are dropped with their trace instead of being exported orphaned from a request span that was dropped.
- Always export a trace whose response is an error, whatever rate matched, via the existing force-keep mechanism.
- Decide content logging from the same matched rule (`log_content`, with `default_log_content` as its fallback), independently of the keep decision. `ROUTER_TRACE_LOG_CONTENT=false` still suppresses content for the whole process.
- Gate the Braintrust exporter on the same sampling decision as the primary OTLP pipeline, sharing one gate so both destinations keep and drop the same spans.
